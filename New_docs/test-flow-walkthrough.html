2. Prerequisites: Setting Up The System

Step A: Admin Creates an Owner

  1. Admin logs in at /login (seed admin account directly in Firebase console)
  2. Goes to /admin/home → "Create Owner Account" form
  3. Fills: Full Name, Email, Password, Phone, Bank Account
  4. On submit: createOwnerAccount creates Firebase Auth user + users/{uid} doc (role: "owner") + owners/owner_{uid} doc (payment details)

Step B: Admin Creates a Parking Lot

  1. In /admin/home → "Create / Update Parking" form
  2. Selects the owner, fills: name, address, lat/lng, capacity (e.g. 20 slots), hourly rate (default 50 ETB), status
  3. On submit: upsertParking validates counters (available+reserved+occupied = capacity), checks owner isn't archived
  4. Result: parkings/{parkingId} doc created with status: "active"

Step C: Owner Creates an Operator

  1. Owner logs in → goes to /owner/home → "Create Operator" form
  2. Fills: name, email, password, selects which parking(s) to assign
  3. On submit: ownerCreateOperator creates Firebase Auth user + users/{uid} doc (role: "operator", ownerId, assignedParkingIds)

Step D: Owner Sets Payment Destination

  1. In /owner/home → "Payment Destination Details"
  2. Sets phone number (for mobile money) and/or bank account number
  3. On submit: ownerUpdatePaymentDetails updates owners/{ownerId} with phone/bankAccountNumber
  4. Drivers will see these details when they choose manual checkout

Step E: Admin Assigns Operator to Parking (if needed)

  1. In /admin/home → "Assign Operator" form
  2. Selects operator and parking, checks "Assign"
  3. Validates owner is not archived before assigning

Step F: Driver Signs Up

  1. Goes to /signup, fills name, email, password
  2. On submit: Firebase Auth user created + users/{uid} doc (role: "driver", walletBalance default: 100.00 ETB)
  3. Redirected to /driver/home

System Ready ✓

Now you have: 1 Admin, 1 Owner, 1 Operator, 1 Driver, 1 Parking Lot with 20 slots at 50 ETB/hr. The driver starts with 100 ETB wallet balance.

3. The Booking Flow (Driver)

1. Select Parking

Driver sees a map with parking markers, a 1000m radius circle, and available slots. Clicks a parking card to select it.

UI Location: DriverHome.js:540-556

2. Fill Booking Form

Driver selects: Parking Location, Plate Number, Start Time (datetime-local), End Time (datetime-local).

Price: 50 ETB/hr base rate + 15% VAT. Hold fee: 20 ETB.

3. Submit Booking

Click "Reserve & Pay 20.00 ETB". Calls createBooking cloud function.

UI: DriverHome.js:247-278

What createBooking Does (functions/index.js:643-749)

  1. Validates: parkingId, plateNumber, startTime < endTime
  2. assertPlateNotInUse: Checks no active session OR reservation exists for this plate anywhere (across all parkings) — this is a NEW hardening added in commit 0e98678
  3. Reads parking in transaction: verifies status = "active", availableSlots > 0, counters invariant holds
  4. Reads driver wallet: checks balance ≥ 20 ETB hold fee
  5. Allocates spot: allocateSpot() — checks active sessions + overlapping time-window bookings for non-conflicting spot ID
  6. Deducts 20 ETB from wallet
  7. Creates booking doc with status "reserved", spotId, reservationCode (e.g., "RES-A3B2C1"), startTime, endTime, expiresAt (startTime + 15 min grace period)
  8. Updates parking counters: availableSlots -1, reservedSlots +1
  9. Returns: bookingId, spotId, reservationCode, directions (text-based navigation), remainingBalance

What The Driver Sees After Booking

  • Wallet: Deducted 20 ETB (e.g., 100 → 80 ETB)
  • Active Reservations card: shows plateNumber, status "reserved", reservationCode, spotId, start time, grace expiration time
  • Booking Flow State badge: "Reserve Complete / Awaiting Check-In"
  • Text Navigation Assistant: Driving directions to the assigned spot, walking directions from pedestrian entrance

Booking Expiration (Scheduled)

Every 5 minutes, the expireBookings scheduled function finds all "reserved" bookings where expiresAt <= now. For each expired booking:

  • Sets booking status → "expired"
  • Updates parking: reservedSlots -1, availableSlots +1
  • Penalizes driver: deducts 15 ETB from wallet (no-show penalty)

Operators can also trigger this manually via the "Trigger Expire Bookings Cron" button in /operator/home → calls expireBookingsManual

4. Check-In Flow (Driver + Operator)

There are 2 check-in paths:

Path A: QR Code Check-In (Recommended)

1. Operator Generates QR

In /operator/home → "Driver Check-In QR" panel. QR auto-refreshes every 55 seconds (token TTL: 60s).

Cloud function: createParkingCheckInToken (index.js:2238-2267)

Creates checkInTokens/{token} doc with expiresAt: now + 60s

Returns deepLink: http://.../driver/checkin-confirm?token={token}

2. Driver Opens QR Link

Driver pastes the QR link/token into /driver/home QR input box, or clicks "Open Deep Link".

Navigates to /driver/checkin-confirm?token=xxx

UI: DriverCheckInConfirm.js

3. Driver Confirms Plate

Driver enters their plate number and clicks "Confirm Check-In".

Cloud function: confirmCheckInFromQr (index.js:2269-2426)

4. Operator Approves

In /operator/home → "Pending QR Check-In Requests" panel, operator sees the request and clicks "Approve" or "Reject".

Functions: approveCheckInRequest / rejectCheckInRequest

On approve: gate alert flashes, session starts.

What confirmCheckInFromQr Does (index.js:2269-2426)

  1. Validates token exists, is "active", and not expired
  2. Checks parking is active and has available slots
  3. Checks no existing pending request for this driver+parking
  4. Checks no active session exists for this plate number (NEW in 0e98678)
  5. Checks no active reservation exists for this plate number (NEW in 0e98678)
  6. If no matching booking found, auto-creates a booking (reserved status, 15-min TTL)
  7. Creates checkInRequests/{id} doc with status "pending"
  8. Marks token as "used"
  9. Returns requestId — driver sees "Waiting for operator approval..."

What approveCheckInRequest Does (index.js:2428-2524)

  1. Validates request is "pending"
  2. Checks parking is active, counters invariant holds
  3. Checks booking is still "reserved"
  4. Checks no active session already exists for this plate (NEW hardening)
  5. Updates booking → "checked_in", checkInAt = now
  6. Updates parking: reservedSlots -1, occupiedSlots +1
  7. Creates session doc with status "active", paymentStatus "unpaid", spotId from booking
  8. Updates request → "approved", records approvedBy, sessionId
  9. Returns sessionId — operator sees green gate unlock alert

What rejectCheckInRequest Does (index.js:2526-2579)

  1. Updates request → "rejected"
  2. If the booking was auto-created (no prior reservation): cancels it, releases parking slot
  3. If the booking was a real reservation: booking stays "reserved" — driver can try again

Path B: Manual Operator Check-In (Walk-In / Reservation)

1. Operator Opens Check-In Form

In /operator/home → "Manual Vehicle Check-In" card

Selects parking, enters plate number, optional reservation code

2. Operator Clicks "Confirm Gate Access"

Cloud function: checkInVehicle (index.js:804-957)

What checkInVehicle Does (index.js:804-957)

  1. Looks up booking by reservationCode OR plateNumber (where status = "reserved")
  2. assertPlateNotInUse: checks no active session for this plate (NEW — now searches across ALL parkings, not just this one)
  3. If booking exists & not expired: updates booking → "checked_in", parking: reserved → occupied
  4. If booking is expired: marks it expired, releases slot
  5. If no booking & allowWalkIn = true: allocates new spot, parking: available → occupied
  6. Creates session doc with status "active", spotId, paymentStatus "unpaid"
  7. Returns sessionId, spotId, gateOpened: true, text directions

After Check-In ✓

Driver's /driver/home now shows an "Active Parking Sessions" card with the plate number, spot ID, entry time. Booking Flow State badge changes to "Approved / Active Session".

Operator's /operator/home shows the session in the active list, and the slot turns from green (available) → red (occupied) in the spot grid.

5. Check-Out & Payment Flow

There are 3 checkout/payment methods:

Method A: Wallet Self-Checkout (Driver)

1. Driver Clicks "Quick Wallet Pay & Checkout"

In /driver/home → "Active Parking Sessions" card → green button.

This is only enabled if: session is active, paymentStatus ≠ "confirmed", no pending manual payment

2. driverCheckOutVehicle Runs (index.js:1138-1277)

  • Validates session is active and belongs to this driver
  • Reads parking hourlyRate
  • Computes charge: duration = ceil((now - entryTime) / 60000) minutes, billedHours = max(1, ceil(duration / 60))
  • baseFare = billedHours × hourlyRate
  • tax = baseFare × 15%
  • amountDue = baseFare + tax
  • Checks wallet balance ≥ amountDue
  • Deducts from wallet, creates payment doc (with 10% admin commission split)
  • Updates session → "completed", exitTime, paymentStatus "confirmed"
  • Updates parking: occupiedSlots -1, availableSlots +1
  • Updates booking → "completed"

3. Receipt Modal Appears

Shows: paymentMethod ("wallet"), durationMinutes, billedHours, baseFare, tax, total amountDue, remainingBalance. Plus a simulated "Exit Gate Unlocked" animation.

Method B: Manual Bank/Phone Payment (Driver → Operator Confirmation)

1. Driver Clicks "Manual Bank/Phone Checkout"

In /driver/home → "Active Parking Sessions" card → outline button.

2. Dialog Shows Payment Details

Driver sees the owner's bank account or phone number (fetched via getParkingPaymentDetails).

Selects method: "Bank Transfer" or "Phone Payment", enters Reference Code (e.g., transaction slip ID).

3. Clicks "Complete Manual Checkout"

Calls submitManualPayment (index.js:1108-1136) → creates paymentRequests/{id} with status "pending"

Session paymentStatus set to "pending". Driver sees "Payment submitted. Waiting for operator confirmation."

4. Operator Confirms Payment

In /operator/home → "Pending Manual Payments Queue" panel. Operator sees plate, amount, method, reference code.

Clicks "Confirm" → confirmManualPayment runs (index.js:1366-1504):

  • Updates session → "completed", exitTime, paymentStatus "confirmed"
  • Updates parking: occupied -1, available +1
  • Creates payment doc with 10% commission split
  • Updates paymentRequest → "confirmed"
  • Gate opens! (green flash)

Alternatively, clicks "Reject" → session stays active, driver can retry.

Method C: Operator Direct Checkout (Cash or Wallet)

1. Operator Searches Vehicle

In /operator/home → "Direct Exit Search & Checkout Gateway" — types plate number.

Matching active sessions appear below.

2. Clicks "Direct Checkout"

Dialog opens: can select "Cash Paid Directly to Operator" or "Wallet Balance Deduction" (only if session has driverId).

3. Clicks "Approve & Unlock Exit Gate"

Calls checkOutVehicle (index.js:959-1106):

  • Same charge calculation as wallet checkout
  • If "wallet": deducts from driver's wallet (checks sufficient balance)
  • If "cash": no wallet deduction, just records the payment
  • Completes session, creates payment record with commission split
  • Frees parking slot
